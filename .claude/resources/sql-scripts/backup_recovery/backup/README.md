# backup_recovery/backup

| Script | What it does | Changes the server |
|---|---|---|
| [backup_history.sql](backup_history.sql) | Last backup dates, types and physical files for a database, from `msdb` | No |
| [search_backups_folder.sql](search_backups_folder.sql) | Finds the most recent differential backup file and builds its path for an FTP transfer | No |
| [clean_backup_history.sql](clean_backup_history.sql) | Deletes old backup and restore history from `msdb` (`sp_delete_backuphistory`) | Yes |
| [olla_hallengreen_backup.sql](olla_hallengreen_backup.sql) | FULL, DIFF and LOG backups with Ola Hallengren's `DatabaseBackup`, plus upload to Azure Blob | Yes |

Deleted history cannot be recovered. Check the cutoff date before running the cleanup.

## Where this fits

- Part of the script library under `.claude/resources/sql-scripts/`, routed by the `/sql-scripts` command.
- Nothing here runs on its own. A DBA, `/sql-scripts` or the `sql-server-dba` agent picks a script and runs it against a server in the fleet.
- The collector's `full_backup_age`, `log_backup_age` and `backup_failed` checks and the `backup_health` MCP tool watch what these scripts produce.
